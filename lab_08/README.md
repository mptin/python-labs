## Где было легко ошибиться

### 1. robots.txt запрещает раздел /search/

Первое, что нужно проверить перед скрапингом. У news.itmo.ru:

```
Disallow: /search/
```

Именно через `/ru/search/?search=...` проще всего искать новости по запросу —
и именно этот путь закрыт. Поэтому сбор построен на ленте главных новостей
`/ru/main_news/`, которая в `robots.txt` не запрещена.

### 2. В ленте лежат не только новости, но и анонсы

Самая тонкая ошибка в этой работе. Естественный шаблон для отбора ссылок —
`/(\d+)/?$`, то есть «адрес, заканчивающийся числом». Под него попадают и
анонсы мероприятий вида `/ru/announce/124118/`.

Ошибки при этом не возникает: страницы анонсов открываются нормально, но
свёрстаны иначе: у них нет счётчика просмотров и нет блока со статьёй.
В результате в таблице появились строки с пустым текстом и пропусками в
просмотрах, а программа отрапортовала «успешно, 0 ошибок».

Обнаружить это удалось только проверкой заполненности полей **после** сбора:

```
views    94.7 %     ← 5 пропусков
text:    min = 0    ← новость с пустым текстом
```

Решение — ужесточить шаблон до `/news/(\d+)/?$`, потребовав наличие сегмента
`/news/` в адресе. После этого заполненность всех полей стала 100%.

Отсюда правило: после скрапинга надо проверять полноту собранных данных.
Молчаливые пропуски опаснее явных ошибок.

### 3. Теги лежат в `ul`, а не в `div`

```html
<ul class="tags"><li><a href="...">Фотоника</a></li>...</ul>
```

Естественный вариант `soup.find('div', {'class': 'tags'})` вернёт `None` —
молча, без исключения, и теги просто потеряются. Правильно искать по классу,
не указывая тег: `soup.find(class_='tags')`.

В качестве запасного варианта теги дублируются в шапке страницы:

```html
<meta property="article:tag" content="Фотоника" />
```

В коде реализованы оба способа.

### 4. Счётчик просмотров спрятан внутри тега `<time>`

```html
<time datetime="2026-09-01T19:18:10+03:00">
  1 Сентября 2026, 19:18<span class="timezone">UTC+3</span><span class="icon eye">5659</span>
</time>
```

Неочевидное место — найти можно только просмотром исходного кода страницы.
Искать нужно `span` с классом `eye`.

### 5. Дату брать из атрибута, а не из текста

Из-за предыдущего пункта `time.get_text()` вернёт
`1 Сентября 2026, 19:18UTC+35659` — дата, часовой пояс и просмотры слипнутся
в одну строку. Атрибут `datetime` содержит чистую дату в формате ISO 8601,
с которым умеет работать pandas.

### 6. Блок с текстом называется по-разному

* обычные новости — `div.js-mediator-article`;
* интервью — `div.post-content`;
* вводный абзац у одних новостей `p.lead`, у других — отдельный блок, у
  третьих его нет.

Решение — искать по очереди и брать первый найденный блок. Внутри него
удаляются подписи к фотографиям, кнопки «поделиться» и скрипты: иначе они
попадут в текст новости.

### 7. При записи csv с текстами нужен `quoting=csv.QUOTE_ALL`

В текстах новостей есть запятые, кавычки и переводы строк. Без принудительного
экранирования файл при обратном чтении «съедет» по столбцам.

### 8. 140 ссылок из ленты дали 90 уникальных новостей

Одна и та же новость попадает в ленту на разных страницах (закреплённые,
«Главное»). Дубликаты убираются через `drop_duplicates(subset='id')`.

### 9. Скрапинг должен быть вежливым

Между запросами стоит пауза 0.7 секунды, передаётся `User-Agent`, а глубина
обхода ограничена константой `MAX_PAGES = 10`.

Полный обход ленты — это сотни страниц и тысячи запросов к чужому серверу.
Для учебной задачи достаточно нескольких страниц, а при необходимости число
легко увеличить одной константой.

### 10. Ошибка одной страницы не должна ронять весь сбор

Каждый запрос обёрнут в `try / except`, проблемные адреса складываются в
отдельный список. Иначе одна недоступная страница на сотой минуте работы
уничтожит весь результат.
